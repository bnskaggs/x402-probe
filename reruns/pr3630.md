# Rerun: A7 long fuse against x402 PR #3630

[x402-foundation/x402#3630](https://github.com/x402-foundation/x402/pull/3630)
adds `spendControls.maxTimeoutSeconds` (default 3600) to `@x402/core`.
This branch reruns attack A7 against it on Base Sepolia, 2026-09-29.

## Setup

1. Clone the PR head (`XFuel-Lab/x402`, branch
   `fix/3614-spendcontrols-max-timeout-signed`, commit `0a753a7`).
2. In `typescript/`: `npx pnpm@11 install --filter "@x402/core..."`, then
   `npx pnpm@11 --filter @x402/core build`, then `npx pnpm@11 pack` in
   `packages/core`.
3. Point this repo's `@x402/core` dependency and an npm `overrides` entry
   at the tarball, placed at `vendor/x402-core-2.27.0-pr3630.tgz` (see\n   `package.json` on this branch; `vendor/` is git-ignored). `npm ls @x402/core` shows one deduped copy.
4. `npm run attack -- A7`, with `LONG_FUSE_SECONDS` set to the window the
   hostile seller requests (default 10 years).

The buyer is the naive one: stock client defaults plus a retry-3 loop.

## Results

| Seller asks | Signed | Buyer lost | Detail |
|---|---|---|---|
| 10 years | 0 | $0.000 | Refused before signing on all 3 attempts (`spendControls.maxTimeoutSeconds (3600s)`) |
| 3601 s | 0 | $0.000 | Refused; boundary is exact |
| 3600 s | 3 | $0.030 | Allowed as designed; 3 signatures valid 1 h, nothing delivered, all 3 cashed after the request ended |

Before the PR, the 10-year case lost $0.030 with signatures valid to 2036
(see the main README).

The cap does what it says. The 3600 s row is expected: the cap bounds how
long a server can hold a signature, not how many the retry loop signs for
one purchase ([#3438](https://github.com/x402-foundation/x402/issues/3438)).
Receipts: `runs/2026-09-29.jsonl`.
